30 FPS PKL 采集与离线转换

已接入本项目的 lerobot-human-inloop-record / lerobot-record 采集入口。
通过 --dataset.storage=pkl 开启；默认 storage=lerobot 保留原保存方式。

1. 在原采集命令中增加/调整以下参数，三台相机各自的 fps 也都设为 30：

  --dataset.storage=pkl
  --dataset.fps=30
  --dataset.video=true
  --dataset.root=/data/raw/piper_1103
  --dataset.push_to_hub=false
  --dataset.pkl_queue_frames=30
  --dataset.pkl_shard_mb=1024
  --dataset.pkl_sync_seconds=1.0
  --play_sounds=false

以上是原采集命令的参数片段。/data/raw/piper_1103 需要换成实际的新目录。
本版不支持 PKL 采集的 --resume=true。
原有环境复位流程保留；reset_time_s 默认 60，按实际操作需求调整。

采集时持续写入未压缩 PKL 分片，不生成 PNG、视频或 Parquet。
每条记录包含三路 RGB 图像、机械臂状态、动作、任务及人在环信息。
timestamp 仍为 frame_index/30；额外的 enqueue_monotonic_ns 只是主机入队时间。
episode 结束提交完成标记，重录的数据标记 discarded 并在转换时跳过。
退出先停止策略和断开设备，再排空 PKL 队列；完成后写 capture.closed.json。

2. 在项目根目录、原 LeRobot 环境中运行离线转换：

  python convert_pkl_dataset.py --input /data/raw/piper_1103/capture.pkl --validate-only
  python convert_pkl_dataset.py --input /data/raw/piper_1103/capture.pkl --no-upload

也可直接把采集目录作为 --input；单独的 part-*.pkl 不能作为入口。
默认输出到相邻的 /data/raw/piper_1103-dataset。
指定输出目录时增加 --output /data/datasets/piper_1103。
输出包括三路 MP4、Parquet 和原格式元数据，保留原 FPS、字段和编码器。
离线转换复用原保存流程，图片每 30 条采样等待写完，限制内存积压。
已存在的本地输出目录或 .converting 目录不会被覆盖。
转换失败后保留中间目录供排查；重新转换时使用新输出目录。

3. 配置自动上传（测试前由你填写目标）：

上传地址格式：用户名@服务器:/绝对目录

将 upload.example.json 复制为转换脚本同目录的 upload.json，并把占位值替换为真实值：

  {
    "upload_target": "用户名@服务器:/绝对目录",
    "upload_port": 22
  }

脚本会自动读取 upload.json。配置好后，每次只需要：

  python convert_pkl_dataset.py --input /data/raw/piper_1103/capture.pkl

也可以通过命令显式指定目标：

  python convert_pkl_dataset.py --input /data/raw/piper_1103/capture.pkl --upload-target 用户名@服务器:/绝对目录

目标中的目录是服务器父目录，最终目录为 /绝对目录/本地输出目录名。
--config 可以指定别处的 JSON 配置；--no-upload 显式关闭本次上传。
独立的 upload_host/upload_user/upload_dir 配置及对应命令参数仍然支持。
需要原采集/转换机器能通过 SSH 密钥免交互登录，远端有 python3 和写权限。
当前实现支持 IPv4/DNS 主机名；实际远程目录应使用无空格的 ASCII 路径。
本项目没有创建 upload.json，未配置任何真实目标或密码。

上传在转换与输出校验成功后执行：
  计算文件清单 -> SCP 临时目录 -> SSH 核对 SHA-256 -> 发布正式目录。
若远端正式目录已存在，仅当文件完全一致时视为成功，否则拒绝覆盖。
上传失败保留本地数据。只重试上传、不重新编码：

  python convert_pkl_dataset.py --upload-only --output /data/raw/piper_1103-dataset

SCP 不做分片断点续传；中断时再次上传，已完整发布且一致的数据会被识别。
失败的远程 .uploading-* 目录保留，核实后可人工清理。

4. 无设备测试：

  python tests/test_pkl_capture.py
  python tests/test_pkl_converter.py
  python tests/test_pkl_record_cleanup.py

启用真实 AV1、Parquet 和视频片段边界回读测试：
  Linux: EVO_PKL_INTEGRATION=1 python tests/test_pkl_capture.py
  PowerShell:
    $env:EVO_PKL_INTEGRATION = '1'
    python tests/test_pkl_capture.py
    Remove-Item Env:\EVO_PKL_INTEGRATION

所有测试均使用合成数据或 mock，不连接相机、机械臂或 SSH 服务器。
采集机上建议先录两段短数据，核对帧数、重录、成功/失败、转换和上传。

容量：三路 640×480 RGB、30 FPS，原始图像约 83 MB/s、20 GB/240 秒。
离线转换还需临时 PNG 和最终数据集空间。队列满时会等待并报警，不静默丢帧。
每秒 fsync 不保证断电零丢帧；硬中断且没有 closed 标记的采集不自动恢复。
PKL 有记录长度和 CRC 包装，使用配套迭代器/转换脚本读取，且只加载可信 PKL。
原始 PKL 不自动删除；视频最终仍按原默认 AV1 进行有损编码。
