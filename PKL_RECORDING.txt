30 FPS PKL 采集与离线转换

已接入本项目的 lerobot-human-inloop-record / lerobot-record 采集入口。
通过 --dataset.storage=pkl 开启；默认 storage=lerobot 保留原保存方式。

1. 在原采集命令中增加/调整以下参数，三台相机各自的 fps 也都设为 30：

  --dataset.storage=pkl
  --dataset.fps=30
  --dataset.video=true
  --dataset.root=/home/apex/data/raw/piper_1103
  --dataset.push_to_hub=false
  --dataset.pkl_queue_frames=30
  --dataset.pkl_shard_mb=1024
  --dataset.pkl_sync_seconds=1.0
  --dataset.pkl_image_encoding=png
  --dataset.pkl_png_compression=1
  --dataset.pkl_encoder_threads=3
  --play_sounds=false

以上是原采集命令的参数片段。/home/apex/data/raw/piper_1103 需要换成实际的新目录。
本版不支持 PKL 采集的 --resume=true。
原有环境复位流程保留；reset_time_s 默认 60，按实际操作需求调整。

采集时默认由三个后台线程将 RGB 无损压缩成等级 1 的 PNG 字节，持续写入 PKL 分片。
不会单独生成 PNG 文件，也不生成视频或 Parquet；PNG 字节存放在 PKL 的图像字段中。
每条记录同时保留机械臂状态、动作、任务及人在环信息，数值字段不做图像压缩。
PNG 新采集为 evo-pkl-v2；旧 RGB evo-pkl-v1 仍能转换。
需要未压缩 RGB 时可显式设 --dataset.pkl_image_encoding=raw。
timestamp 仍为 frame_index/30；额外的 enqueue_monotonic_ns 只是主机入队时间。
episode 结束提交完成标记，重录的数据标记 discarded 并在转换时跳过。
退出先停止策略和断开设备，再排空 PKL 队列；完成后写 capture.closed.json。

2. 在项目根目录、原 LeRobot 环境中运行离线转换：

  python convert_pkl_dataset.py --input /home/apex/data/raw/piper_1103/capture.pkl --validate-only
  python convert_pkl_dataset.py --input /home/apex/data/raw/piper_1103/capture.pkl --no-upload

也可直接把采集目录作为 --input；单独的 part-*.pkl 不能作为入口。
默认输出到相邻的 /home/apex/data/raw/piper_1103-dataset。
指定输出目录时增加 --output /home/apex/data/datasets/piper_1103。
输出包括三路 MP4、Parquet 和原格式元数据，保留原 FPS、字段和编码器。
默认显示进度条：Validate PKL（校验帧数）、Frames prepared（图片准备）、
Episodes encoded（完成视频编码的段数）、Local SHA256（本地校验字节）和 Upload（上传字节）。
上传条同时显示速度、已用时间与预计剩余时间；上传 100% 后仍需等待远端 SHA-256 校验成功。
视频编码等待期间会持续刷新已用时间；帧准备 100% 不代表整段视频已编码完成。
重定向日志不需要进度条时增加 --no-progress。
离线转换自动识别旧 RGB / 新 PNG PKL，复用原视频和元数据保存流程。
PNG 字节直接写成临时 PNG，避免重复压缩；旧 RGB 路径每 30 条采样等待写完，限制内存积压。
已存在的本地输出目录或 .converting 目录不会被覆盖。
转换失败后保留中间目录供排查；重新转换时使用新输出目录。

3. 配置自动上传（测试前由你填写目标）：

上传地址格式：用户名@服务器:/绝对目录

将 upload.example.json 复制为转换脚本同目录的 upload.json，并把占位值替换为真实值：

  {
    "upload_target": "用户名@服务器:/绝对目录",
    "upload_port": 22
  }

脚本会自动读取 upload.json。配置好后，每次只需要：

  python convert_pkl_dataset.py --input /home/apex/data/raw/piper_1103/capture.pkl

也可以通过命令显式指定目标：

  python convert_pkl_dataset.py --input /home/apex/data/raw/piper_1103/capture.pkl --upload-target 用户名@服务器:/绝对目录

目标中的目录就是最终训练数据集根目录，不再追加本地输出目录名。
例如指定 baiyuntian@10.61.5.3:/nfs/baiyuntian/assets/caiji/test，
上传后直接得到 test/data、test/meta、test/videos。
该规则同时适用于 --upload-target、--upload-dir 和 JSON 配置。
--config 可以指定别处的 JSON 配置；--no-upload 显式关闭本次上传。
独立的 upload_host/upload_user/upload_dir 配置及对应命令参数仍然支持。
认证支持 SSH 密钥，或私有 upload.json 中的 upload_password 密码字段。
upload_password 留空时使用 SSH 密钥；Linux 上填写密码后会通过临时 SSH_ASKPASS 自动认证。
该配置文件已被 Git 忽略，建议 chmod 600 upload.json，不要把真实密码写进公开源码。
也可以用 --upload-password-env 指定保存密码的环境变量名称。
密码不放入 SSH 命令行，临时认证脚本用完清理；Windows 端继续使用 SSH 密钥。
远端需要 python3 和目标目录写权限；第一次连接需确认服务器主机指纹。
当前实现支持 IPv4/DNS 主机名；实际远程目录应使用无空格的 ASCII 路径。
upload.example.json 不包含真实目标或密码；实际 upload.json 只保存在使用它的机器上。

上传在转换与输出校验成功后执行：
  计算文件清单 -> SSH 流式传输到临时目录 -> SSH 核对 SHA-256 -> 发布正式目录。
远端目录不存在或为空时可上传；已有数据时，仅当文件完全一致才视为成功，否则拒绝覆盖。
上传失败保留本地数据。只重试上传、不重新编码：

  python convert_pkl_dataset.py --upload-only --output /home/apex/data/raw/piper_1103-dataset

SSH 文件流按实际发送的文件字节显示进度，不依赖 SCP 的终端进度输出。
目前不做分片断点续传；中断时再次上传，已完整发布且一致的数据会被识别。
失败的远程 .uploading-* 目录保留，核实后可人工清理。

         EVO_PKL_INTEGRATION=1 python tests/test_pkl_png.py

    python tests/test_pkl_capture.py
    python tests/test_pkl_png.py

所有测试均使用合成数据或 mock，不连接相机、机械臂或 SSH 服务器。
采集机上建议先录两段短数据，核对帧数、重录、成功/失败、转换和上传。

容量：三路 640×480 RGB、30 FPS，原始图像约 83 MB/s、20 GB/240 秒。
此前 76 上 PNG 等级 1 的相机短测从约 827 MB 降到 261 MB；按该场景估算约 6.3 GB/240 秒。
实际体积随场景变化。后台压缩使用有界队列，磁盘或 CPU 跟不上时仍会等待。
离线转换还需临时 PNG 和最终数据集空间。队列满时会等待并报警，不静默丢帧。
每秒 fsync 不保证断电零丢帧；硬中断且没有 closed 标记的采集不自动恢复。
PKL 有记录长度和 CRC 包装，使用配套迭代器/转换脚本读取，且只加载可信 PKL。
原始 PKL 不自动删除；视频最终仍按原默认 AV1 进行有损编码。
